# Gomoku Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver local two-player and three-level computer Gomoku with zoom-driven board growth, score history, final-board snapshots, and replay.

**Architecture:** A pure sparse-board engine owns coordinates, moves, exact-five win rules, and replay. The UI projects that model into a pannable/zoomable grid; AI and persistence consume engine interfaces without reaching into React state.

**Tech Stack:** React 19.2.6, TypeScript 5.9.3, Vitest 4.1.10, CSS transforms, Web Worker-compatible AI adapter, versioned localStorage

## Global Constraints

- This plan starts only after the foundation and Number Hunt plans pass.
- Modes are local two-player and child versus computer.
- Setup includes names, distinct colors, piece theme, starting player, and Easy/Medium/Hard computer level.
- The board starts at 20 x 20 and zoom-driven growth reaches at most 50 x 50.
- Once expanded during a match, logical dimensions never contract.
- A win is exactly five consecutive stones and is invalid only when both line ends are blocked.
- The exact five winning stones blink briefly, then remain highlighted; reduced motion skips blinking.
- Local two-player scores are grouped by normalized player pair.
- Keep the 50 most recent completed game records with snapshot and replay.
